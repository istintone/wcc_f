# 29. 試合の映像の動きを高度に(2026-11-26)

オーナーの相談: 試合中のピッチの演出が、ふわふわと移動しているだけに見える。もっと高度でリアルに。放物線以外に、スルーパスやグラウンダーのクロスも描きたい。

## 29.1 今の作りと「ふわふわ」の原因

- 選手: 目標の位置へ、毎フレーム残りの距離の一定の割合ずつ近づく(指数の追従)。動き出しも止まり方も同じなめらかさで、走るより漂う
- 選手の絵: 1人1枚の動きのある絵。向きはチーム(ホーム / アウェイ)で決まり、走っても止まっても蹴っても同じ
- ボール: 同じく目標へ一定の割合で。パスでもシュートでも同じ放物線

## 29.2 段階1: 走る・止まる / 体の動きと向き(実装済み)

- 選手は位置と速度を持つ(render.js `kinStep`)。目標へ加速して走り、近づくと減速して止まる(到着の減速 = √(2 × 減速 × 残りの距離))。最高速はスピードの能力で変わる(`TUNING.view.kin`: v0 + spd × vSpd)。ボールに絡む人は 1.5倍速く、加減速も強い。ドリブルする人はボールに合わせる
  - 例: 21m 先へ 0.25秒で最高速近くまで加速し、約1秒で止まる
- 体の動き(`drawMan`): 走る速さに合わせて上下に揺れ(歩みの位相)、前に傾き、着地で少し潰れる。進む向きを向くよう左右反転(止まっているときはボールの方)。蹴る瞬間(プレーの始めの 22%)はボールを送る向きへ大きく踏み込む

## 29.3 段階1: ボールの軌道をプレーごとに(実装済み)

| プレー(試合の処理の ch) | 軌道(`ballPath`) |
|---|---|
| 短い繋ぎ・縦パス・散らし・ポストプレー | ground: 地を這い、出だしが速く減速して届く |
| スルーパス・ラストパス | through: 速く転がり(残像)、受け手は後ろから走り込んで追いつく |
| クロス(サイド・ウイング) | 場面ごとに3回に1回はグラウンダー(lowx: 低く速く、残像)、それ以外は高い放物線 |
| ロングフィード・ロングキック・セットプレーのクロス | loft: 高い放物線、落ちて小さく弾む |
| サイドチェンジ・サイドへ展開・アーリークロス・スロー | drive: 低めの弾道 |
| シュート | shot: 速い直線(わずかに浮く)と残像 |
| ドリブル・キックオフ | carry: 足元の少し前で、小さくタッチしながら運ぶ |

- 残像(`drawTrail`)は、速いボール(シュート・スルーパス・グラウンダーのクロス)の直前の6か所を薄く重ねる

## 29.4 段階2: プレーの「間」と役割の動き(実装済み)

- オーナーの指摘(段階1): 上下の揺れのひょこひょこした感じを遅めに → 1歩の長さ 2.6m → 8m(速く走っても揺れは1秒に数回)、揺れの大きさ 0.06 → 0.045
- プレーの「間」(`ballPath`): 蹴る前の溜め(プレーの時間の最初の 12%。シュートは 8%)はボールが足元に留まり、蹴る人は送る向きへ踏み込む。ボールは 90% の時点で届き、残りはファーストタッチで止まる(ドリブルには入れない)
- 役割の動き(`roleMoves`。ボールに絡む人は動かさない)
  - 守備: ディフェンスラインの高さをそろえる(平均へ 75%)/ いちばん近い人は保持者のすぐ手前(自陣側)まで寄せて止まる
  - 攻撃: 保持者の近くの2人が斜め後ろ・斜め前に動いて三角形(70%)
  - セットプレー(コーナー・フリーキックのクロス): 両チームのフィールドの選手がゴール前に集まる
  - ゴールのあと(2.2秒): 決めたチームは得点者のまわりに集まり、相手は自陣へ戻る
- 数値は `TUNING.view.kin`(wind・windShot・arrive・line・pressGap・sup・celebMs)

## 29.5 段階3: 中継のカメラと足元の演出(実装済み)

- 中継のカメラ(`camUpdate`): ボールを横に追い、ゴール前(端から 0.28 以内)では寄る(中盤 1.08倍 → ゴール前 1.22倍)。縦はボールを 40% だけ追う。なめらかさ 0.7秒。画面の外が見えないよう、動ける範囲で止める。背景(drawPitch)と選手・ボールに同じ拡大・移動をかける
- 足元の演出(`drawFx`。芝の上に描く)
  - 砂埃: 止まった状態から急に加速したとき(速さの割合 0.3 未満 → 0.6 超)と、蹴った瞬間に、足元の後ろへ3つ(同じ人は 0.65秒あける)
  - スライディングの跡: 「鉄壁のスライディング」で奪った人の足元に、芝の跡を 1.6秒
  - ゴールネットの揺れ(`drawGoal`): 決まった瞬間に奥へふくらみ、揺れながら 1.4秒で戻る(揺れている間はネットの目を描く)
- 数値は `TUNING.view.cam`・`TUNING.view.fx`
- どれも映像の側だけで、試合の結果には触れない

## 29.6 後半はキックオフの並びから / セットプレーを分かりやすく(2026-11-26)

- オーナーの希望: ハーフタイムのあとは、キックオフと同じポジションから再開。セットプレー系の演出も分かりやすく
- 後半: ハーフタイムに入ったとき `viewKickoff()` で並び・ボール・カメラ・演出をキックオフのときに戻す(試合の始めも同じ関数)。ハーフタイムの画面の後ろで、選手は自陣のキックオフの並びに立つ
- セットプレー(main.js): コーナーキック・直接フリーキック・PK の始めに「CORNER KICK」「FREE KICK」「PENALTY KICK」の帯を出し、`TUNING.view.sp.pre`(0.9秒)試合を止めて並び・ボールを置く位置を見せる(リプレイでは出さない)
- 並び(render.js `roleMoves`)
  - コーナーキック・フリーキックのクロス: キッカーはボールの位置、ほかはゴール前に密集(段階2のまま)
  - 直接フリーキック: 守る側の4人(`wallN`)が、ボールからゴールへ 9.15m の所に、ボールとゴールを結ぶ線に直角に並んで壁を作る。ほかはゴール前とこぼれ球に備える位置へ
  - PK: キーパーはゴールライン、キッカー以外はペナルティエリアの外(弧のまわり)
- 溜めの間は、ボールを置く位置に金の楕円の印(明滅)を描き、カメラをもう少し寄せる(+0.08)
