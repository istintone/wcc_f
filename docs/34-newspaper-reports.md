# 34. 新聞とレポートをコンテンツとして作り込む(2026-11-27 設計)

オーナーの希望(docs/33 §33.10): 新聞・レポートは、ゲームをナラティブにするものなので雰囲気を残す。そのうえで、別途コンテンツとして作り込む。

## 34.1 いまあるもの

| もの | 中身 | 作り |
|---|---|---|
| クラブ新聞(WEEKLY NEWS) | 1号 = 1枚。題字(略称 SPORT)・号数と値段の帯・一面の話題(優勝・覚醒・昇格・新加入・スタジアム…・試合の結果)・写真・スコア・VOTO(MVP の採点)・見出しと小見出し・本文(ドロップキャップ)・監督の談話・RUMORS(ゴシップ) | `paper.js`(記事のデータ)・`clubui.js` の `paperHtml`。前後の号は ‹ › |
| 視察レポート | 01 総合評価(LEAD / BEHIND / EVEN の判子)・02 戦力比較(6軸)・03 要注意人物(KP・攻守の柱・スーパーサブ)・04 所見。秘書の親密度で黒塗りが減る | `scoutRepModalHtml` |
| 選手のレポート(PLAYER REPORT) | 01 SPEC(カード・適性マップ・6能力・SKILL・KP・ROLE)・02 STATS(★・信頼度・調子・タグ) | `sqDetailHtml` |

## 34.2 新聞: 1号を紙面にする(→ §34.7 で3面に)

イタリアのスポーツ紙(ピンクの紙・採点 VOTO・ゴシップ)の手触りを強める。1号を4面にし、横にめくる。

| 面 | 中身 | 使うデータ |
|---|---|---|
| 1面 一面 | 今と同じ(その試合のあとのいちばん大きな話題) | 既存 |
| 2面 試合 | **採点(PAGELLE)**: 出た選手全員の VOTO と一言の寸評(「左サイドを何度も破った」など、記録から作る)/ 先発の並びの図 / 得点の経過 / 支配率・シュート | `matchRatings`・試合の記録 |
| 3面 大会 | リーグの順位表(上位と自分のまわり)/ 他会場の結果 / 次の相手の予想(相手の KP・調子のよい選手) | リーグの表・日程・相手の育成(docs/31) |
| 4面 ゴシップと広告 | RUMORS(今のまま)/ 秘書のコラム(親密度で口調が変わる)/ サポーターの投書 / スポンサーの広告(契約中のスポンサーの業種と☆で絵柄が変わる)/ 次の試合の告知 | 秘書・スポンサー・サポーター数 |

- 寸評・投書・コラムは `paper.js` と同じく**文の型に試合の中身を当てはめて**作る(同じ試合なら同じ文)
- 新聞を開いたときは1面。下のつまみで面を移る(横にすべる)。号は今と同じ ‹ ›

## 34.3 視察レポート: 綴じた書類の束に

| 足すもの | 中身 |
|---|---|
| 05 予想布陣 | 相手の陣形の図に、KP・攻守の柱・調子のよい選手の印 |
| 06 直近の戦績 | 相手の直近5試合の勝ち負けの並び(実際の日程から) |
| 07 相手監督 | 性格(戦い方)・チームスタイル(読めるのは親密度しだい)・ハーフタイムに出しそうな指示 |
| 秘書の手書きメモ | 親密度が高いときだけ、余白に付箋のような手書きの一言(助言) |
| 見た目 | クリップで留めた紙・ページの端の番号・判子は今のまま |

## 34.4 選手のレポート: 人物の調書に

| 足すもの | 中身 |
|---|---|
| 03 SCOUT'S NOTE | 型・特徴・スキルから作る人物評(2〜3文)。例:「中盤まで降りて受け、前を向くと一気に加速する。ゴール前での落ち着きは群を抜く」 |
| 04 THIS TERM | この任期の成績(出場・得点・アシスト・MVP の回数・平均の採点) |
| 05 HISTORY | 育成の記録(★が上がった試合・覚醒・タグを得た試合)を年表のように |
| 06 PARTNERS | 連携の深い選手(太線・黄金線)の顔写真と関係の言葉 |

## 34.5 新しいレポート(足すか決めたい)

- **MATCH REPORT**(試合のあと): アナリストの1枚。チャンスの数・危なかった場面・効いたスキルと KP・次への課題。ロッカールームの前後に開ける
- **TERM REPORT**(任期の終わり): オーナーからの評価書。目標・指令の結果・年俸の上げ下げ(docs/28)の理由を書類で

## 34.6 進め方

1. この文書の中身でよいかを決める(とくに 34.5 を入れるか)
2. 見本(新聞の4面・視察レポートの束・選手の調書)を作って確かめる
3. 文の型(寸評・投書・コラム・人物評)を `paper.js` に足し、画面に入れる

## 34.7 見本へのオーナーの指摘(2026-11-27)

- 書体が見にくい → **ゲームと同じ書体にそろえる**(英字と数字は Barlow Condensed、日本語は端末の標準のゴシック)。明朝・手書きの書体は使わない(秘書のメモも同じゴシック)
- 新聞は **1号あたり2〜3面**(1面あたりの情報が少なかった)→ 3面にまとめた
  - 1面: 一面の話題 + 試合のデータ(支配率・シュート・得点の経過)+ 監督の談話
  - 2面: 採点(出た選手全員を2列で)+ 順位表 + 他会場の結果
  - 3面: 次の相手の予想 + ゴシップ + 秘書のコラム + サポーターの投書 + スポンサーの広告

## 34.8 本体に入れた(2026-11-27)

- オーナーが見本を確かめた(新しいレポート MATCH / TERM はこの回では入れない)
- 新聞(`paper.js` の `paperPages`・`clubui.js` の `paperHtml` / `paperPage2` / `paperPage3`): 1号3面。下の 1 / 2 / 3 か横のスワイプで面をめくる。号は今と同じ左右の ‹ ›
  - 1面: 今の一面 + 試合のデータ(支配率・シュート / 枠内・得点の経過)
  - 2面: 採点(出た選手全員を2列。寸評は役割の群 × 出来の文の型 `PAPER_PAG`)・順位表(上位5 + 自分)・他会場の結果(リーグの節)
  - 3面: 次の相手(KP・相手監督の型)・ゴシップ・秘書のコラム(`PAPER_COL`)・サポーターの投書(`PAPER_LETTER`)・契約中のスポンサーの広告
  - ピンクの紙。めくる紙面は傾けない。書体はゲームと同じゴシック
  - 前からある号(2面・3面の材料が無い)は、1面とゴシップだけを今まで通りに出す
- 視察レポート(`scoutMoreHtml`): 05 予想布陣(相手の並びに KP と好調の印)・06 直近の戦績(同じリーグなら順位と勝ち負け)・07 相手監督(戦い方・チームスタイル(親密度で読める数)・後半の指示の傾向)・秘書の手書きのメモ(親密度の段 2 以上。相手の DF でいちばん足の遅い選手と、こちらでいちばん速い攻め手)
- 選手の調書(`dossierHtml`): SCOUT NOTE(型の書き出し `PTYPE_NOTE` + いちばんの強み `STRONG_NOTE` + スキル)・THIS TERM(出場・得点・アシスト・平均の採点)・GROWTH HISTORY(★・覚醒・タグ・MVP を新しい順に)・LINK PARTNERS(太線・黄金線の選手)
- 新しい記録: `S.tstat`(この任期の選手の成績。任期の始めで空に)・`S.g.pl[id].hist`(育成の記録。最大8件)・`S.league.round`(この節の他会場の結果)

## 34.9 面は縦に、横は前後の号(2026-11-27。オーナーの指摘)

- 指摘: 新聞の枠の中だけで面が切り替わる演出に違和感がある。下へのスワイプで面を読み、横のスワイプをバックナンバーにしたほうがよい
- 面(1〜3)は縦に並べ、下へスクロールして読む(面の番号のボタンはやめた)
- 横のスワイプで前後の号へ(左へ払うと次の号、右へ払うと前の号。縦の動きが大きいときは号を替えない)。号を替えると、紙面ごと横から入る(次の号は右から、前の号は左から)。左右の ‹ › も同じ

## 34.10 新しいレポート(2026-11-27。オーナー「レポートもたして」)

### MATCH REPORT(試合のあとのアナリストの1枚)

- 試合のあとに材料を残す(`S.mrep`。直近の試合だけ。`matchReportData`)。HOME の新聞の1行の下に「MATCH REPORT」の札が出て、押すと下から出るシートで開く(次の試合が終わるまで)
- 01 数字(支配率・シュート・枠内・パス成功を両チームの棒で)/ 02 シュートの記録(ゴールは必ず入れ、ほかと合わせて最大16本を時間の順。ゴール・セーブ・枠外・ブロック、PK・FK・ヘディング)/ 03 効いたもの(採点の上位3人と、効いたスキルの回数)/ 04 次への課題(数字から1〜2つ。枠に飛ばない・打たれすぎ・保持できない・パスが通らない → どの練習が効くか)
- 作成は秘書。書類は視察レポートと同じ紙

### TERM REPORT(任期の終わりのオーナーからの評価書)

- 任期の終わりの画面に「TERM REPORT」のボタン。押すと下から出るシートで開く
- 01 成績(勝ち負け・勝率・賞金・取ったタイトル)/ 02 評価(評価 P と求め R。監督称号・勝率・優勝の内訳)/ 03 目標と指令(今の任期の終わりの表示と同じ)/ 04 年俸(前 → 次、増額・減額)/ 05 オーナーより(評価が求めの 1.25倍以上 = 大きく上回る、求め以上 = 届いた、未満 = 届かなかった、の言葉)
- 判子は EXCELLENT / APPROVED / REVIEW。署名はクラブの理事会(BOARD)

## 34.11 視察の画面はスカウティングレポートから(2026-11-27。オーナーの指摘)

- 指摘: スカウティングレポートの出来がよいので、視察の画面は最初からレポートが出ている形に
- 視察の画面(SCOUT)は、上にスカウティングレポート(紙の書類をそのまま置く。`scoutRepModalHtml(true)`)、その下に OPPONENT SQUAD(相手の盤面。選手を押すとカード)。レポートを開くボタンはやめた

## 34.12 相手の SQUAD はレポートに吸収(2026-11-27。オーナーの指摘)

- 指摘: OPPONENT SQUAD の情報はレポートとほとんど重なる。予想布陣は上下を逆に。控えを含めたメンバー(ポジションと選手名)を載せる
- 視察の画面はスカウティングレポートだけ。OPPONENT SQUAD はやめた(SEASON から相手を見るときの盤面はそのまま)
- 05 予想布陣: 相手の GK が下(相手の SQUAD と同じ向き)。点は背番号、下に「ポジション 名前」。KP の枠と好調の印はそのまま。点を押すと相手の選手のカード
- 05 の下にメンバー: 先発11人 → SUB → 控え5人。背番号・ポジション・名前(KP、CAP / PK / FK / CK)・カードの数字・調子のタグ。行を押すと相手の選手のカード

## 34.13 SEASON から見る相手もスカウティングレポート(2026-11-27。オーナーの指摘)

- 指摘: SEASON から参照できる対戦相手の情報も、スカウティングレポートに合わせる
- SEASON の日程・順位表から相手を押すと、浮いている窓にスカウティングレポート(`scoutRepModalHtml(true,fx0)`)。次の試合の相手なら視察と同じもの。それ以外の相手は、大会の行(大会・GAME)を出さない
- 黒塗り(UNKNOWN)は視察と同じく秘書の親密度しだい。05 予想布陣とメンバーを押すと相手の選手のカード
- 相手の SQUAD の盤面(`oppSquadHtml` / `oppTokenHtml`)は使う所がなくなったので消した
