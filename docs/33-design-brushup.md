# 33. デザインの全体ブラッシュアップ会議(2026-11-27)

テーマ(オーナー): Web ゲームとして見たときのデザインの詰めの甘さ。ボタンや文言の表示場所、パネルのデザインと細かな意匠、統一感のある IF(ヘッダー・フッター・パンくず・同じ種類の表示は同じデザインと CSS)、ボタンを押したときの振る舞い、UIUX の洗練。
観点: アートディレクター / ウェブデザイナー / ゲームクリエイター / ゲームデザイナー。
材料: 390px で撮った画面(HOME・準備の4段・SQUAD・CARDS・SEASON・CLUB・試合・視察レポート・選手詳細・カード排出・チャット)と、CSS の作り(base.css・theme.css・white.css・neon.css が重ねて上書きしている)。

## 33.1 総評

- **良いところ**: 1つずつの画面には見せ場がある(試合のモニターと盤面、視察レポートの紙、カード排出、カードの裏)。赤 × 白のテーマと、斜めに切った意匠の方向は合っている
- **甘いところ**: 画面ごとに作り方がばらばらで、「同じ種類のもの」が画面によって違う見た目と振る舞いをしている
  - ボタンが少なくとも7種類の見た目(赤の斜めのグラデーション・灰色・白の枠・チップ・金・黒・小さな赤)で、優先度の決まりが無い
  - 見出しの作り(赤い斜めの線 + 日本語 + 灰色の補足の数字 / 英字の斜体 / 黒い帯)が画面ごとに違う
  - 閉じる・戻るの場所と形(赤い丸の ×・黒い四角の ×・紙の右上の ×・「‹ 視察」・左上の ×)がそろっていない
  - パネル(白い紙・紺の帯・金の左線・紙のレポート・暗いフロート)の使い分けの決まりが無い
- 原因: CSS が4枚(base → theme → white → neon)の上書きで育ち、theme.css の末尾に `!important` の上書きが積み重なっている。**部品(コンポーネント)とトークンの決まりを先に作り、画面をそれに載せ替える**のが本筋

## 33.2 アートディレクターの観点(見た目の言語と統一感)

### 見えたこと
- 明るい紙の世界(クラブハウス)と、暗い紺の世界(試合・カード排出・カードのフロート・視察の盤面)が、決まり無く行き来する
- 書体: 英字の斜体の太字(FRIENDLY MATCH・PLAYER REPORT)、細い英字(WCC F ・ SQUAD REPORT)、日本語のゴシックが混ざり、大きさの段階がばらばら
- 赤の使い方: 主ボタン・見出しの線・負け・ケガ・絶好調・KP・NEXT と、意味の違うものが同じ赤
- CLUB のトロフィーは灰色の仮の絵のまま。地の透かしのボールが中身の下に大きく出て、文字の上に重なる所がある

### 提案
- **AD1 2つの世界を決める**: 「紙(クラブハウス = 監督室の書類)」と「スタジアム(試合・排出・フロート = 夜の照明)」。どの画面がどちらかを表にし、パネル・文字色・ボタンの見え方を世界ごとに1組だけにする
- **AD2 書体の段階**: 見出し(英字の斜体・大)/ 小見出し / 本文 / 補足 / 数字(Barlow 系)の5段だけに。英字の見出しは「英字の斜体 + 日本語は使わない」か「日本語 + 英字の小さな添え字」のどちらかに統一
- **AD3 色の意味を固定**: 赤 = 主な操作と自チーム、金 = 報酬・称号・KP、青 = 相手・情報、緑 = 良い状態、灰 = 使えない。負け・ケガは赤ではなく暗い赤か灰に
- **AD4 トロフィーとアイコンの絵を作る**: 13種のトロフィーの絵(仮の灰色のシルエットをやめる)、タブのアイコンの線の太さをそろえる
- **AD5 地の透かしを控えめに**: 不透明度を下げ、パネルの下にだけ見えるように

## 33.3 ウェブデザイナーの観点(レイアウト・部品・CSS)

### 見えたこと
- ヘッダー: タブの画面はクラブの帯(エンブレム・名前・OVR・任期・資金・サポーター)。準備の流れは「× + パンくず + 試合の行」。視察と戦略方針は、さらにその下に独自の見出し(「視察 秘書が相手の SQUAD を整理した [視察レポート]」「戦略方針 ‹ 視察」)
- フッター: タブの画面はタブバー。準備の流れは下に1つのボタンだが、見た目が段ごとに違う(灰色の無効・白の枠・赤)
- 見出しの横に補足の数字や説明が残っている(「日程 過去5試合と、この先10試合・第12/100試合」「カード 28種・28枚・登録16人」「トロフィー 第1任期・獲得1/13種・1回」「監督ライセンス 初回だけ。名前はあとで…」「節をスキップ 試合なし・任期は減らない」)→ 方針(説明は消していく)に合わない
- 文字の切れ: 日程の「KING'S CLUB CUPは敗退…」、実況の行、長いクラブ名
- 無効のボタン(「この練習で決定」)が灰色の上の灰色で読めない
- モーダルが4系統(暗いフロート・下からのシート・紙のレポート・小さな窓)で、閉じる場所と形が違う

### 提案
- **WD1 デザイントークンを1か所に**: 色・余白(4 / 8 / 12 / 16 / 24)・角(0 / 2 / 6)・影(2段)・文字の段(AD2)を `:root` の変数に。4枚の CSS の上書きをやめ、部品は1枚(components.css)に集める。`!important` を減らす
- **WD2 ボタンの体系**: 主(赤の斜めの帯)/ 副(白に赤の枠)/ 控え(文字だけ)/ 危険(暗い赤)/ チップ(選ぶもの)/ 小(表の中)。1画面に主ボタンは1つ。無効はうすく(読める濃さで)、理由はボタンの上ではなく秘書の言葉で
- **WD3 画面の骨組みを3つに**
  - タブの画面: 上 = クラブの帯 / 中 = 内容 / 下 = タブバー
  - 準備の流れ: 上 = 戻る + パンくず(4段)+ 試合の行 / 中 = 内容 / 下 = 次へのボタン(いつも同じ場所・同じ形)。段ごとの独自の見出しはやめ、パンくずの今の段がその役をする
  - 試合と場面: 全画面。閉じる・次へは右下(TOUCH HERE と同じ場所)
- **WD4 見出しの部品を1つに**: 「赤い斜めの線 + 見出し」だけ。横の補足の数字と説明は消す(必要な数字は中身の側に)
- **WD5 モーダルの部品を1つに**: 下から出るシート(スマホの標準)に寄せる。閉じるは右上の同じ ×、背景を押しても閉じる。紙のレポートは「シートの中の紙」にする
- **WD6 文字の切れを無くす**: 長い文は2行まで許して省略しない、または短い言い方に

## 33.4 ゲームクリエイターの観点(手触り・演出・振る舞い)

### 見えたこと
- ボタンを押したときの反応が部品ごとに違う(音だけ・色だけ・何も無い)。押した瞬間の沈み込みが無いものが多い
- 画面の切り替えが一瞬で全部描き直す(タブ・準備の段・シートの開閉)。どこから来てどこへ行ったかが分かりにくい
- 待ち時間の表示(両端から縮むゲージ)は試合だけ。準備や結果の「次へ」は急に出る
- 報酬の瞬間(★が上がる・タグが付く・覚醒・称号)は、知らせの文だけのことが多い

### 提案
- **GC1 押したときの振る舞いを1つに**: 押す → 0.08秒で 0.97倍に沈む + 少し暗く → 離して戻る + 音(種類ごとに3つ: 決定・選ぶ・戻る)。Android はごく短い振動(navigator.vibrate)
- **GC2 画面の切り替えに方向を**: タブは横にすべる、準備の段は右から入る、戻るは左へ、シートは下から。0.2〜0.25秒
- **GC3 報酬の演出の型**: ★が上がる・覚醒・タグ・称号は、同じ「光って出てくる帯」の型で(カード排出の光り方と同じ言語)
- **GC4 無効と待ちを分かりやすく**: 押せない理由があるときは、秘書の吹き出しが揺れて知らせる(説明の文は増やさない)

## 33.5 ゲームデザイナーの観点(情報の優先度・流れ・言葉)

### 見えたこと
- HOME: 次の試合の札のあとに、秘書の出来事(受ける・断る)が縦に積まれ、何から片付けるかが分かりにくい
- 準備の4段: 毎試合4段を通る。急ぎたいときの近道が無い
- 言葉: 英字と日本語が混ざる(FRIENDLY MATCH・準備をはじめる・SQUAD・日程・トロフィー)。同じものの呼び方が画面ごとに違うことがある
- 押せる所が小さい: 盤面の札の★・タグ、表の中の小さなボタン

### 提案
- **GD1 HOME の優先度**: 「次の試合」が主。秘書の出来事は1つずつ(残りの数だけ見せる)にし、答えると次が出る
- **GD2 準備の近道**: 準備の中にいつも「すぐ試合へ」(残りの段を既定のまま進める)。2回目からは前の試合の設定を引き継ぐ
- **GD3 言葉の決まり**: 大会・場面の名前は英字(本家の雰囲気)、操作と説明は日本語、タブは英字。表(用語集)を1枚作り、画面の文言をそろえる
- **GD4 押せる所は 44px 以上**: 盤面の札の中の小さな印は押せない飾りにして、札そのものを押す

## 33.7 オーナーに決めてほしいこと

1. **2つの世界**(紙のクラブハウス / 夜のスタジアム)の分け方でよいか。それとも全部を1つの世界(白 × 赤)に寄せるか
2. **言葉**: 見出しは英字中心(本家の雰囲気)か、日本語中心か
3. **モーダル**: 下から出るシートに統一してよいか(今の中央のフロートのカードは、シートの中に大きなカードを出す形になる)
4. **準備の近道**(すぐ試合へ)を入れてよいか
5. 進め方の順(土台 → 骨組み → 世界と書体 → 絵と演出)でよいか

## 33.8 オーナーの答え(2026-11-27)

1. **全体を単一のテーマ(白 × 赤)にそろえる**(本家 WCCF がそうだった)。AD1 の「2つの世界」はやめ、試合・排出・フロートも白 × 赤の言語に寄せる
2. **見出しは英字中心**
3. モーダルは下から出る形で OK。ただし**新聞・レポートなど、それぞれの雰囲気は残す**(ゲームをナラティブにするため)。統一するのは出方・閉じ方・枠の決まりだけ
4. **「すぐ試合へ」は入れない**。このゲームは WCCF を踏襲する: **選手をそろえ、育成していくことがプレイヤーの主な行動で、試合はその結果を確かめるもの**。試合中の操作は、育てた結果を生かして意図したチームとして振る舞わせることに重みがある(GD2 はやめる)
5. 進め方は基本 OK。**変更は事前にサンプルで確かめてから適用する**(期待と大きく違えば中止・変更する)。各段の前にサンプル(部品の見本と、代表の画面の前後)を出す

## 33.9 第1段(土台)を本体に(2026-11-27)

- 見本(第1段の部品と HOME・準備の前後)をオーナーが確かめ、適用した
- 見出し: すべての `h3` を英字の太い斜体に(SCHEDULE・CARDS・TROPHIES・THIS TERM・CLUB・MANAGER・CAREER RECORD・HISTORY・SPONSOR・STADIUM・FACILITIES・TEAM STYLE・HALF-TIME ORDERS・TITLE SET・CLUB OFFERS・MANAGER LICENSE・CLUB SETTINGS・CONTRACT・SECRETARY・COACHING NOTE・GROWTH GRAPH・COMPETITIONS・SETTINGS ほか)。横の補足の数字と説明を消した
- 準備: パンくずを英字に(TRAINING / COACHING / SCOUT / TACTICS)。段ごとの独自の見出し(「チーム練習」「個別指導」「視察 秘書が…」「戦略方針」)をやめ、パンくずの今の段がその役をする。視察レポートのボタンは副ボタン、戦略方針の戻るは「‹ SCOUT」
- ボタン: 副ボタン(白に赤の枠)を「節をスキップ」(→ SKIP)・視察レポート・個別指導の早めの「視察へ」にそろえた。無効の主ボタンは読める濃さに
- 押したときの振る舞い: ボタン・タブ・押せる札はどれも、押すと 0.97倍に沈み少し暗くなる。Android はごく短い振動
- 色の意味: 負けの印は暗い赤。次の試合の札の帯は赤(自チームの次の一手)
- HOME: 答えが要る出来事(出来事の申し込み・スタジアムの改修)は1つずつ出し、ほかは「1 / 2」の数だけ
- まだ残っていること(第2段以降): ヘッダーの帯の監督名の重なり(「テスト 監督 監督」)、試合・場面の画面、モーダルの枠、書体の段の全体への当てはめ

## 33.10 第2段(骨組み)を本体に(2026-11-27)

- 見本(画面の骨組み3つ・シート・切り替えの向き)をオーナーが確かめた。「自然な形なら戻るを足してよい」「新聞・レポートは別途コンテンツとして作り込む」(→ 第2段のあとの別の作業)
- 準備の下の帯: 左に戻る・右に次へ(どの段でも同じ場所)。戻るのは自然に戻れる段だけ: 視察 → 個別指導(‹ COACHING)、戦略方針 → 視察(‹ SCOUT)。チーム練習は済ませたら戻れない。次へは英字(SCOUT / TACTICS / KICK OFF。チーム練習の決定は、選んだ練習と強度を添えるので日本語のまま)
- 画面の切り替えの向き: タブは並びの右のタブへ行くと右から、左へ行くと左から入る。準備の段は進むと右から、戻ると左から(0.24秒)
- モーダル: 下から出るシートに(つまみ・右上の同じ × ・開いたときだけ下からせり上がる)。中の雰囲気(紙のレポート・選手のレポート・暗い台のカード)はそのまま
- ヘッダーの「監督」の重なりは、テストで入れた名前(「テスト 監督」)のためで、不具合ではなかった

## 33.11 第3段(書体・言葉の決まり・文字の切れ)を本体に(2026-11-27)

- 見本をオーナーが確かめ、適用した
- 書体の7段: CAPTION 10.5 / S 11.5 / M 13 / L 15 / HEAD 20 / XL 28 / DISPLAY 44 以上。base.css・theme.css・white.css の文字の大きさ 555 か所のうち 385 か所を、近い段へ機械的にそろえた(10.5 より小さいものは 10.5 へ)。カード・盤面の札・試合の画面・場面(排出・結果)は絵や盤面の一部なのでそのまま(このため、その中には 10.5 より小さい文字が残る)
- 言葉の決まり: 場所・画面・書類の名前は英字(パンくず・見出し・行き先のボタン)、操作と文は日本語。変えたもの: 「KP設定」→「KP」、「SKIP」→「スキップ」(操作なので日本語に戻した)、「⇄ SQUAD と交代」→「⇄ 入れ替える」、日程の注記「〜の出場条件を満たせば、そちらに出る」→「〜 に出られればそちら」
- 文字を切らない: 日程の注記・新聞の1行・ミッション・練習の説明・最近の試合・トロフィーの名前などは「…」で切らず2行まで折り返す。盤面の札の名前など、幅の決まった所だけは切る

## 33.12 第4段(絵と演出)を本体に(2026-11-27)

- 見本をオーナーが確かめ、適用した
- トロフィーの絵(`trophyIconSvg`): 格ごとの形はそのままに、金・銀・銅の金属の照り・刻まれた帯・木の台座を描いた。取っていないものは棚に彫られた輪郭だけ
- 報酬の帯(`infoBar`): 知らせを「光って横から出てくる帯」にそろえた。見出しは英字(★ UP・AWAKEN・TAG・TITLE・TROPHY・INFO)、色は意味どおり(個人の★ = 黄・特殊の★ = 青・覚醒 = 金・称号と優勝 = 黒に金・タグ = 赤・ほか = 黒)。絵文字は見出しに置き換えた
- 地の透かし: 赤い帯は細く淡く、格子とボールのタイルはやめ、ロゴの透かしは小さく

## 33.13 不具合: モーダルの × が押せない・画面が縮む(2026-11-27)

- オーナーの指摘: モーダルのほとんどで、× や前後の ‹ › を押しても閉じず、画面がぎゅっと中央に縮む
- 原因: 第1段の「押すと沈む」(`scale:.97`)を、ボタンとタブに加えて data-act を持つすべての要素に掛けていた。モーダルの背景(押すと閉じる)や枠も data-act を持つので、中を押すと `:active` が入れ物にも付き、モーダル全体が縮む。縮んだぶん × が指の下からずれ、押した場所と離した場所が食い違って押せなかった
- 直し方: 沈むのはボタンとタブだけ。短い振動も同じくボタンとタブだけ
